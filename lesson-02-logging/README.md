# Урок 2. Логирование: SLF4J и Logback

## Цель урока
Понять, почему `System.out.println` не подходит для реальных проектов, и научиться использовать профессиональные библиотеки логирования: SLF4J и Logback.

---

## Теория

### 1. Почему не System.out.println?
В базовом курсе мы использовали `System.out.println` для вывода информации. Это нормально для учебных примеров, но в реальных приложениях так делать нельзя:
* **Нет уровней важности.** Непонятно, это просто информация, предупреждение или критическая ошибка.
* **Нет даты и времени.** При падении сервера вы не узнаете, когда именно произошла ошибка.
* **Нет источника.** Непонятно, в каком классе и в какой строке вывелось сообщение.
* **Нельзя отключить.** Чтобы убрать отладочный вывод, приходится удалять код вручную.

### 2. SLF4J и Logback
В Java-разработке принято разделять «фасад» (интерфейс) и «реализацию».
* **SLF4J** (Simple Logging Facade for Java) — это тот самый фасад (интерфейс). Вы пишете код, используя SLF4J, и он не зависит от конкретной библиотеки.
* **Logback** — это популярная и мощная реализация, которая «под капотом» выполняет всю работу (пишет логи в консоль или файлы).

### 3. Добавление зависимостей
Чтобы использовать логирование, в `pom.xml` нужно добавить две зависимости:

~~~xml
<dependencies>
    <!-- Фасад (интерфейс) -->
    <dependency>
        <groupId>org.slf4j</groupId>
        <artifactId>slf4j-api</artifactId>
        <version>2.0.12</version>
    </dependency>

    <!-- Реализация (движок) -->
    <dependency>
        <groupId>ch.qos.logback</groupId>
        <artifactId>logback-classic</artifactId>
        <version>1.5.3</version>
    </dependency>
</dependencies>
~~~

Logback автоматически подхватится, как только окажется в classpath (в зависимостях), и SLF4J начнет использовать его.

### 4. Уровни логирования
Сообщения делятся на уровни важности (от низшего к высшему):
* `TRACE` — самый детальный уровень (пошаговое выполнение).
* `DEBUG` — отладочная информация (полезно при разработке).
* `INFO` — обычные информационные сообщения (например, "Приложение запущено").
* `WARN` — предупреждения (что-то пошло не так, но программа продолжает работать).
* `ERROR` — ошибки (программа не может выполнить операцию).

### 5. Как использовать в коде
В каждом классе, где нужно логирование, создается статическая переменная логгера:

~~~java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class MyClass {
    // Создаем логгер для текущего класса
    private static final Logger logger = LoggerFactory.getLogger(MyClass.class);

    public void doSomething() {
        logger.info("Это информационное сообщение");
        logger.warn("Это предупреждение");
        logger.error("Это ошибка");
    }
}
~~~

*Примечание: в IntelliJ IDEA можно использовать шаблон `log` (напечатать и нажать Tab), чтобы быстро сгенерировать эту строку.*

### 6. Параметризованные сообщения
В SLF4J можно использовать плейсхолдеры `{}` вместо конкатенации строк через `+`. Это быстрее и безопаснее.

~~~java
String userName = "Иван";
int age = 25;

// Плохо (строка склеивается всегда, даже если лог отключен)
logger.info("Пользователь " + userName + " вошел в систему, возраст: " + age);

// Хорошо (строка склеивается только если лог включен)
logger.info("Пользователь {} вошел в систему, возраст: {}", userName, age);
~~~
